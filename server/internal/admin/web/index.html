    Groups are who or what a policy applies to
    A user group holds people (by Entra group, or picked by hand); a device group holds PCs (by computer name or platform). A person or PC can be in several groups. Assign groups to policies on the Policies page.
    How a policy is picked
    For each kind of policy, the first one in the list with an assigned group that includes the user or PC applies. Every kind ends with a Default for everyone. Move policies up or down to set their priority.

    Server addresses

    The apps connect to the main address. If they can't reach it at all, they automatically use a backup address and switch back once the main one works again. Sessions carry over without signing in again. Backups are sent to every app, so they're known even while the main address is down.

    Installer: /BACKUP=vpn2.example.com · GPO/Intune: BackupServers

    Certificates
    Optional, one pattern per line; a certificate must match one. * matches anything, $hostname is the computer's name, $upn the user's sign-in name, $user the part before @. Device certificates are matched on their CN and DNS names, user certificates on email, UPN and CN. Empty = any name.

    Blocked connects show the reason to the user and in the audit log.

    Duo

    For sign-in policies that use Duo as an extra sign-in step. After the user signs in, the server sends a Duo Push (or a phone call, if that's their device) and connects once they approve. In the Duo Admin Panel, add an Auth API application and copy its details here.

    Office networks, countries, speed tests

    These are now policies, so different groups can get different settings: see Policies. Device approval is there too (the Devices page switch edits the Default).

    Office networks

    When a PC is on the corporate network, the agent disconnects the VPN and won't connect, so traffic goes out the office network directly. Any one rule is enough. Rules are cached on each PC, so they work before connecting.

    One per line.

    Device tunnel (before sign-in)

    With nobody signed in to SecureTunnel, Windows PCs connect with their device certificate so the Windows sign-in screen can reach your domain controllers: first logons without cached credentials, password changes and resets, Group Policy and Intune at boot. Only approved devices whose certificate (from a trusted CA under Device trust) names the computer can connect. The tunnel reaches only these subnets, and the gateways enforce that. When a user signs in to SecureTunnel, their full tunnel replaces it.

    One per line.

    Country access

    Users can sign in and connect only from these countries, plus any extra countries or trips set on their account in Users. The country comes from the user's public IP when they sign in, as detected by Cloudflare. Every blocked attempt is in the audit log.

    Allowed for everyone

    Search by name or code; click a country to add or remove it.

    Speed tests

    Agents measure their internet speed outside the VPN (only to this host; everything else stays in the tunnel) and their speed through the VPN. Results appear in each session's details.

    Move to another gateway

    The app switches within a few seconds. Their tunnel IP changes to the new gateway's pool, so open connections (calls, file copies) restart.

    Placement rules

    New users go to the gateway with the fewest users. A gateway at or over any of these limits stops taking new users until it recovers. If every gateway is over its limits, users still connect to the least busy one.

    Update the app

    The app reconnects by itself after updating; the user doesn't sign in again.

    Address range

    Tunnel IPs for users on this gateway come from this range; the gateway itself takes the first address. Each gateway needs its own range, and your network must route it to the gateway.
